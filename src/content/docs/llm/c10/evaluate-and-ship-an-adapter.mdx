Before shipping, compare the frozen base and adapter on the same held-out prompts using the same decoding and rubric. Measure what changed: instruction adherence, answer format, factual correctness and critical regressions. A lower training loss does not establish a better release. Run prompt-only and retrieval baselines when they address the same task.

Record an <Term id="adapter-version" /> with base checkpoint, tokenizer and chat template revision, target modules, rank and scale, training data version and relevant software versions. Load the adapter into the matching base. If you merge factors into the base weights for deployment, keep an unmerged source artifact for rollback and run an equivalence check under the planned precision.

This example imposes two gates. The candidate must meet a minimum absolute accuracy gain and must not regress on any marked critical case. That policy is intentionally strict for this fixture. Define thresholds before seeing held-out results and use C9's uncertainty and slice analysis for actual release decisions.

An adapter is a candidate for stable behavioural changes. Retrieved evidence still belongs in the request for facts that must remain current and verifiable.

## Worked example

The candidate gains fifty percentage points overall and fails because of a critical regression.

```python
def release_gate(before, after, critical, min_gain):
    if not before or len(before) != len(after) or len(before) != len(critical):
        raise ValueError("need aligned, nonempty outcomes")
    gain = (sum(after) - sum(before)) / len(before)
    regression = any(flag and old and not new for old, new, flag in zip(before, after, critical))
    return gain, gain >= min_gain and not regression

print(release_gate([1, 0, 0, 0], [0, 1, 1, 1], [True, False, False, False], 0.25))
```

```text title="Output"
(0.5, False)
```

Use both compatibility evidence and held-out outcomes before promoting an adapter.
