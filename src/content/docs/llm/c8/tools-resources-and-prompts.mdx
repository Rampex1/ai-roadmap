An MCP tool represents an operation, such as searching a public catalogue by title. A <Term id="mcp-resource" /> represents accessible data, such as a library hours page. A prompt is a reusable interaction template, such as a librarian's suggested format for summarizing a source. The MCP documentation describes tools as generally model-controlled, resources as application-controlled and prompts as user-controlled. Hosts can still impose presentation and approval policy.

Use a resource when the host already knows which object to load. Use a tool when an operation needs structured arguments and a result computed at call time. A prompt template helps a user start a task with a consistent rubric. It should never be the only control on what data the server may return.

The example models a known resource URI and a text body. A URI identifies an object in the example registry and does not imply a browser or network fetch. Treat resource text as data and keep permissions in the application and server.

## Worked example

The URI selects a document that already exists in the public registry.

```python
def read_public_resource(uri, resources):
    if uri not in resources:
        return {"status": "not_found"}
    return {"status": "ok", "uri": uri, "text": resources[uri]}

print(read_public_resource("library://hours", {"library://hours": "North opens at 9."}))
```

```text title="Output"
{'status': 'ok', 'uri': 'library://hours', 'text': 'North opens at 9.'}
```

Keep resource selection and access checks separate from instructions found in the resource text.
