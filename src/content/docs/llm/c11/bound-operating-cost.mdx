A <Term id="request-budget" /> can include a wall-clock deadline, maximum model calls, token cap and cost limit. Input and output token prices may differ. Multiply each count by its corresponding price per million tokens, then divide by a million. Actual billing can also include cached-input rates, model-dependent reasoning tokens or tool fees. Use the provider's measured usage for reconciliation.

Reserve capacity before work starts. Estimate the output cap rather than assuming a short answer and keep some time for rendering a deadline fallback. For concurrent tool work, budget each admitted action so several simultaneous decisions cannot all claim the same remaining allowance.

Control load at the application boundary using bounded concurrency and queues. Track when you reject or defer work. As demand rises, a service with unbounded queues can appear healthy until latency spikes. Compare cost per successful request in addition to the per-call bill when retries are common.

## Worked example

The input costs 0.002 USD and the output costs 0.0008 USD.

```python
def token_cost(input_tokens, output_tokens, input_per_million, output_per_million):
    return (input_tokens * input_per_million + output_tokens * output_per_million) / 1_000_000

print(round(token_cost(1000, 100, 2, 8), 4))
```

```text title="Output"
0.0028
```

Reserve work before dispatch and compare estimates with measured usage after the request.
