In [F4](/foundations/f4/derivatives-and-learning/) you saw *why* a small step against the gradient
lowers the loss: the linear approximation gives $\Delta L \approx -\eta\lVert\nabla L\rVert^2 \le 0$.
This lesson is about the word "small". How big can a step be before the argument breaks, what happens
when it does, and why the same learning rate can be too big in one direction and too small in another?

## The algorithm

<Term id="gradient-descent" /> repeats one update:

$$
\boldsymbol{\theta}_{t+1} = \boldsymbol{\theta}_t - \eta\, \nabla L(\boldsymbol{\theta}_t)
$$

- $\boldsymbol{\theta}_t$ is the parameter vector after $t$ steps; $\boldsymbol{\theta}_0$ is the
  starting guess.
- $\nabla L(\boldsymbol{\theta}_t)$ is the [gradient](/foundations/f4/gradient/) there: the direction of
  steepest increase.
- $\eta$ (eta) is the <Term id="learning-rate" />, a positive number you choose.

As code, for any number of parameters, keeping every point visited so we can plot or inspect the path:

```python
import numpy as np

def gradient_descent(grad, theta0, lr, steps):
    theta = np.array(theta0, dtype=float)
    history = [theta.copy()]
    for _ in range(steps):
        theta = theta - lr * grad(theta)
        history.append(theta.copy())
    return np.array(history)          # shape (steps + 1, number of parameters)
```

`theta - lr * grad(theta)` builds a new array, so the caller's `theta0` is never changed.
`history[-1]` is the final point.

## One dimension: what the learning rate does

Take the simplest bowl, $f(x) = x^2$, with $f'(x) = 2x$ and minimum at $0$. One step gives

$$
x_{t+1} = x_t - \eta \cdot 2x_t = (1 - 2\eta)\, x_t
$$

So every step multiplies $x$ by the same factor $r = 1 - 2\eta$, and after $t$ steps
$x_t = r^t x_0$. Everything depends on $r$:

| Learning rate | Factor $r = 1 - 2\eta$ | Behaviour |
|---|---|---|
| $0 < \eta < 0.5$ | $0 < r < 1$ | Shrinks steadily, never crossing 0 |
| $\eta = 0.5$ | $r = 0$ | Lands exactly on the minimum in one step |
| $0.5 < \eta < 1$ | $-1 < r < 0$ | Overshoots to the other side each time, but shrinks: zigzags in |
| $\eta = 1$ | $r = -1$ | Bounces between $x_0$ and $-x_0$ forever |
| $\eta > 1$ | $r < -1$ | Each overshoot is bigger than the last: **diverges** |

```python
import numpy as np

def run(lr, x=1.0, steps=5):
    xs = [x]
    for _ in range(steps):
        x = x - lr * 2 * x          # f(x) = x**2, so f'(x) = 2x
        xs.append(x)
    return np.round(xs, 3)

for lr in [0.1, 0.5, 0.9, 1.1]:
    print(f"lr {lr}:", run(lr))
```

```text title="Output"

lr 0.5: [1. 0. 0. 0. 0. 0.]
lr 0.9: [ 1.    -0.8    0.64  -0.512  0.41  -0.328]
lr 1.1: [ 1.    -1.2    1.44  -1.728  2.074 -2.488]
```

**Curvature sets the limit.** For a general bowl $f(x) = \frac{a}{2}x^2$ (curvature $f''(x) = a$), the
same algebra gives $r = 1 - \eta a$. Convergence needs $|r| < 1$, which means

$$
0 < \eta < \frac{2}{a}
$$

A sharply curved valley (large $a$) forces a small learning rate. Near a minimum, any smooth loss looks
like such a bowl, which is why this little calculation explains a lot of real training behaviour.

:::caution[Divergence is fast]
With $r = -1.2$ the distance grows by 20% per step: after 50 steps it is about $9{,}000$ times larger,
and if you keep going it eventually overflows to `inf` and then `nan`. A loss that suddenly shoots up or turns
into `nan` usually means the learning rate is too large.
:::

## Two dimensions: one learning rate, two curvatures

Now $f(x, y) = x^2 + 10y^2$, with $\nabla f = (2x,\ 20y)$. The two coordinates update independently:

$$
x_{t+1} = (1 - 2\eta)\,x_t, \qquad y_{t+1} = (1 - 20\eta)\,y_t
$$

The $y$ direction is 10 times more curved, so it needs $\eta < 2/20 = 0.1$, while $x$ alone would
tolerate $\eta < 1$. The steep direction sets the learning rate, and the shallow direction then crawls.

```python
f = lambda p: p[0]**2 + 10 * p[1]**2
grad = lambda p: np.array([2 * p[0], 20 * p[1]])

for lr in [0.01, 0.05, 0.09, 0.11]:
    h = gradient_descent(grad, [3.0, 1.0], lr, 50)
    print(f"lr {lr:4}: after 50 steps theta = {np.round(h[-1], 4)}, f = {f(h[-1]):.3g}")
```

```text title="Output"
lr 0.01: after 50 steps theta = [1.0925 0.    ], f = 1.19
lr 0.05: after 50 steps theta = [0.0155 0.    ], f = 0.000239
lr 0.09: after 50 steps theta = [0.0001 0.    ], f = 2.37e-08
lr 0.11: after 50 steps theta = [   0.     9100.4382], f = 8.28e+08
```

At $\eta = 0.11$, just past the limit, $y$ explodes while $x$ converges happily. At $\eta = 0.09$, just
under it, $y$ has factor $1 - 1.8 = -0.8$: it flips sign every step. The path zigzags across the narrow
valley while creeping along it:

```python
h = gradient_descent(grad, [3.0, 1.0], 0.09, 6)
print(np.round(h, 3))
```


The ratio of the largest to the smallest curvature (here $20 / 2 = 10$) is called the **condition
number**. The larger it is, the longer and thinner the valley, and the slower plain gradient descent
gets. Two fixes appear later: rescaling the inputs so the valley is round
([lesson 5](/foundations/f6/practical-optimisation/)), and optimisers that remember past steps or scale
each coordinate separately ([lesson 4](/foundations/f6/momentum-and-adam/)).

## When does it stop?

Gradient descent never reaches the minimum exactly; it gets closer forever. In practice you stop when
one of these happens:

- a fixed budget of steps runs out;
- the gradient is tiny: $\lVert\nabla L\rVert < \varepsilon$ for some tolerance $\varepsilon$, since at a
  minimum the gradient is zero;
- the loss has stopped improving by more than some small amount.

[Lesson 5](/foundations/f6/practical-optimisation/) adds the most important practical rule: stop when
the loss on held-out data stops improving.

## Non-convex: where you start matters

On the two-valley curve $f(x) = x^4 - 3x^2 + x$ from
[lesson 1](/foundations/f6/what-is-optimisation/), gradient descent simply rolls into whichever valley it
starts above:

```python
g = lambda x: 4 * x**3 - 6 * x + 1          # f'(x)
for x0 in [-0.5, 0.5, 2.0]:
    x = x0
    for _ in range(200):
        x = x - 0.02 * g(x)
    print(f"start {x0:5}: ends at x = {x:.3f}, f = {x**4 - 3*x**2 + x:.3f}")
```

```text title="Output"
start  -0.5: ends at x = -1.301, f = -3.514
start   0.5: ends at x = 1.131, f = -1.070
start   2.0: ends at x = 1.131, f = -1.070
```

Starting at $0.5$ or $2.0$ finds only the local minimum. Gradient descent is a *local* method: it
follows the slope it can see, and nothing in the update rule knows about the deeper valley on the
other side of the hill.

## Summary

- Gradient descent: $\boldsymbol{\theta}_{t+1} = \boldsymbol{\theta}_t - \eta\nabla L(\boldsymbol{\theta}_t)$.
- On $\frac{a}{2}x^2$ each step multiplies the error by $1 - \eta a$: it converges for
  $0 < \eta < 2/a$, zigzags when $\eta > 1/a$, and diverges beyond $2/a$.
- With several directions, the most curved one caps the learning rate and the flattest one sets the
  speed. A large condition number means slow progress and zigzags.
- Stop on a step budget, a small gradient norm, or a stalled loss. On non-convex losses the starting
  point decides which minimum you reach.
