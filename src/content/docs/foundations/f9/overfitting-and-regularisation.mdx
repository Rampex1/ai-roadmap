The moons network in the [last lesson](/foundations/f9/training-an-mlp/) had 300 training examples and
354 parameters, and it generalised well. Give a big network very little data, though, and it will learn
the training set by heart, noise included. That is <Term id="overfitting" />, and this lesson shows how
to spot it and three standard ways to fight it.

## Three sets, three jobs

Detecting overfitting and fixing it both involve choices: how long to train, how strong a penalty to
use. If we made those choices by looking at the test set, the test score would no longer be an honest
estimate of performance on new data, because we would have tuned to it. So the data is split three ways:

| Set | Used for |
|---|---|
| **Training** | computing gradients and updating the weights |
| **Validation** | choosing settings: epochs, penalty strength, architecture |
| **Test** | one final measurement, after every choice is made |

F7 did this with [cross-validation](/foundations/f7/cross-validation/). Here we use a deliberately tiny training set, 30 noisy moons,
and large validation and test sets so their numbers are reliable.

## Watching a network overfit

The code extends last lesson's with two optional ingredients, an L2 penalty `lam` and dropout `p_drop`,
both explained below. With both at 0 it is plain full-batch gradient descent on a 2 → 100 → 100 → 2
network with over 10,000 parameters, which is far too many for 30 points.

```python
import numpy as np
from sklearn.datasets import make_moons

X, y = make_moons(n_samples=1000, noise=0.3, random_state=0)
X_train, y_train = X[:30], y[:30]          # deliberately tiny
X_val, y_val = X[500:750], y[500:750]
X_test, y_test = X[750:], y[750:]

def init(sizes, rng):
    return [[rng.normal(0, np.sqrt(2 / a), size=(a, b)), np.zeros(b)]
            for a, b in zip(sizes[:-1], sizes[1:])]

def forward(params, X, p_drop=0.0, rng=None):
    A, inputs, masks = X, [], []
    for i, (W, b) in enumerate(params):
        inputs.append(A)
        Z = A @ W + b
        if i == len(params) - 1:
            return Z, inputs, masks
        A = np.maximum(0, Z)
        M = (rng.random(A.shape) >= p_drop) / (1 - p_drop) if p_drop > 0 else np.ones_like(A)
        masks.append(M)
        A = A * M                                  # dropout (training only)

def cross_entropy(logits, y):
    m = logits.max(axis=1, keepdims=True)
    logp = logits - m - np.log(np.exp(logits - m).sum(axis=1, keepdims=True))
    return -logp[np.arange(len(y)), y].mean(), logp

def loss_and_grads(params, X, y, lam=0.0, p_drop=0.0, rng=None):
    logits, inputs, masks = forward(params, X, p_drop, rng)
    loss, logp = cross_entropy(logits, y)
    loss += lam / 2 * sum((W ** 2).sum() for W, _ in params)     # L2 penalty
    dZ = np.exp(logp)
    dZ[np.arange(len(y)), y] -= 1
    dZ /= len(y)
    grads = [None] * len(params)
    for i in reversed(range(len(params))):
        W, b = params[i]
        A = inputs[i]
        grads[i] = [A.T @ dZ + lam * W, dZ.sum(axis=0)]           # + lam * W from the penalty
        if i > 0:
            dZ = (dZ @ W.T) * masks[i - 1] * (A > 0)
    return loss, grads

def evaluate(params, X, y):
    logits, _, _ = forward(params, X)              # no dropout at evaluation time
    loss, _ = cross_entropy(logits, y)
    return loss, (logits.argmax(axis=1) == y).mean()

def train(lam=0.0, p_drop=0.0, epochs=3000, lr=0.1, seed=0, log=()):
    rng = np.random.default_rng(seed)
    params = init([2, 100, 100, 2], rng)
    history = []
    for epoch in range(1, epochs + 1):
        _, grads = loss_and_grads(params, X_train, y_train, lam, p_drop, rng)
        for (W, b), (dW, db) in zip(params, grads):
            W -= lr * dW
            b -= lr * db
        val_loss, _ = evaluate(params, X_val, y_val)
        history.append(val_loss)
        if epoch in log:
            tr_loss, tr_acc = evaluate(params, X_train, y_train)
            print(f"epoch {epoch:4}: train loss {tr_loss:.3f} (acc {tr_acc:.2f})   "
                  f"val loss {val_loss:.3f}")
    return params, history

params, history = train(log=(100, 200, 500, 1000, 2000, 3000))
```

```text title="Output"
epoch  100: train loss 0.277 (acc 0.90)   val loss 0.366
epoch  200: train loss 0.207 (acc 0.90)   val loss 0.367
epoch  500: train loss 0.078 (acc 1.00)   val loss 0.447
epoch 1000: train loss 0.022 (acc 1.00)   val loss 0.644
epoch 2000: train loss 0.006 (acc 1.00)   val loss 0.899
epoch 3000: train loss 0.003 (acc 1.00)   val loss 1.034
```

The training loss heads to zero and training accuracy hits 100%: the network has memorised all 30
points. Meanwhile the validation loss bottoms out early and then **rises** to three times its best value.
The network is bending its boundary around individual noisy points and becoming confidently wrong on
new ones. The **gap** between training and validation loss is the thing to watch.

## L2 regularisation

Large weights let a network make sharp, confident turns. L2 <Term id="regularisation" /> adds a penalty
on their size to the loss:

$$
L_\text{total} = L_\text{data} + \frac{\lambda}{2}\sum_\ell \lVert W_\ell\rVert^2
$$

where $\lVert W\rVert^2$ is the sum of the squared entries and $\lambda \ge 0$ sets the strength. Biases
are usually left out. The gradient of the penalty is simply $\lambda W$, so each update becomes

$$
W \leftarrow W - \eta\,(dW + \lambda W) = (1 - \eta\lambda)\,W - \eta\,dW
$$

With plain SGD, the factor $1 - \eta\lambda$ shrinks the weights before the data-gradient update.
That is equivalent to applying **weight decay** directly. The equivalence need not hold for adaptive
optimisers. The [Research lesson on decoupled weight decay](/research/b4/decoupled-weight-decay/) shows
how AdamW handles the two terms. In the code, look for `L2 penalty` and `+ lam * W`.

## Dropout

<Term id="dropout" cap /> attacks overfitting differently. During training, each hidden unit is switched off
(set to 0) at random with probability $p$, independently for every example and every step. The network
can never rely on any one unit being present, so it spreads what it knows across many units instead of
building fragile combinations that only fit the training points. A common intuition: each step trains a
different random "thinned" sub-network, and the full network behaves like an average of them.

The surviving units are divided by $1 - p$. This **inverted dropout** keeps each unit's *expected*
value unchanged: it is $0$ with probability $p$ and $a/(1 - p)$ with probability $1 - p$, which averages
to $a$. At evaluation time dropout is simply **switched off** and nothing needs rescaling. In the code,
`M` is the mask of zeros and $1/(1 - p)$ values, and the backward pass multiplies by the same mask,
because a dropped unit passed nothing forward and receives nothing back.

## Comparing the fixes

```python
for name, kw in [("no regularisation", {}), ("L2, lambda 0.01", {"lam": 0.01}),
                 ("dropout, p 0.5", {"p_drop": 0.5})]:
    params, history = train(**kw)
    tr_loss, tr_acc = evaluate(params, X_train, y_train)
    _, val_acc = evaluate(params, X_val, y_val)
    print(f"{name:18} train acc {tr_acc:.2f}  val loss {history[-1]:.3f}  val acc {val_acc:.2f}")
```

```text title="Output"
no regularisation  train acc 1.00  val loss 1.034  val acc 0.88
L2, lambda 0.01    train acc 1.00  val loss 0.334  val acc 0.90
dropout, p 0.5     train acc 1.00  val loss 0.856  val acc 0.90
```

Some honest observations:

- **Accuracy hides a lot.** All three get 88 to 90% on validation, but the unregularised network's
  validation loss is three times higher: its wrong answers are made with great confidence. Watch the loss,
  not just the accuracy.
- **L2 helped most here**, cutting the validation loss from 1.03 to 0.33.
- **Dropout helped a little** on this tiny network after 3000 steps. It tends to shine in large networks
  trained on more data; here it mainly slowed the memorisation down.
- $\lambda = 0.01$ and $p = 0.5$ were not tuned. Choosing them is exactly what the validation set is for:
  try a few values, keep the one with the best validation loss.

## Early stopping

The simplest fix of all: stop training when the validation loss stops improving, and keep the weights
from the best epoch. This is <Term id="early-stopping" />. Since the validation loss is noisy, we wait for
a number of epochs without improvement, called the **patience**, before stopping.

```python
params, history = train()
best = int(np.argmin(history))
print(f"lowest val loss {history[best]:.3f} at epoch {best + 1}; final val loss {history[-1]:.3f}")
```

```text title="Output"
lowest val loss 0.342 at epoch 229; final val loss 1.034
```

Stopping near epoch 229 would have given a validation loss almost as good as L2's, for a tenth of the
training time. A real implementation copies the parameters whenever the validation loss reaches a new
best and restores that copy at the end (the exercise below works out when to stop).

Finally, with every choice made on the validation set, the test set is used **once** to report how the
chosen model does on new data:

```python
params, _ = train(lam=0.01)
print(f"test accuracy of the chosen model: {evaluate(params, X_test, y_test)[1]:.2f}")
```

```text title="Output"
test accuracy of the chosen model: 0.89
```

:::tip[The best regulariser is more data]
All of these methods are workarounds for having too little data for the model's size. If you can get
more data, or use a smaller model, do that first. With 300 training points instead of 30, the same
unregularised network ends with a validation loss of 0.24 instead of 1.03.
:::

## Summary

- Overfitting: training loss keeps falling while validation loss rises. Choose settings on a validation
  set and touch the test set once, at the end.
- L2: add $\frac{\lambda}{2}\sum\lVert W\rVert^2$ to the loss and $\lambda W$ to each weight gradient; each
  step shrinks the weights (weight decay).
- Dropout: during training zero each hidden unit with probability $p$ and divide survivors by $1 - p$;
  switch it off for evaluation.
- Early stopping: track validation loss, keep the best weights, stop after `patience` epochs without
  improvement.
