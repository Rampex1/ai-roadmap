To train a network with gradient descent we need $\partial L/\partial w$ for every weight. A small MNIST
network has a hundred thousand weights; large models have billions. Estimating each derivative with
finite differences would need two forward passes per weight. <Term id="backpropagation" cap /> gets all of
them from **one** forward pass and **one** backward pass. It is nothing more than the
[chain rule](/foundations/f4/chain-rule/) from F4, applied in a careful order.

## A network small enough to do by hand

One input, one hidden tanh unit, one output, squared error:

$$
z = w_1x + b_1, \qquad h = \tanh z, \qquad \hat y = w_2h + b_2, \qquad L = (\hat y - y)^2
$$

Take $x = 1$, target $y = 0$, and parameters $w_1 = 0.5$, $b_1 = 0$, $w_2 = 2$, $b_2 = 0.1$.

**Forward pass.** Compute and *keep* every intermediate value:
$z = 0.5$, $h = \tanh 0.5 = 0.4621$, $\hat y = 2(0.4621) + 0.1 = 1.0242$, $L = 1.0242^2 = 1.0491$.

**Backward pass.** Start at the output with $\partial L/\partial L = 1$ and walk back one node at a time.
At each node, multiply the gradient arriving from above by that node's **local derivative**:

| Node | Local derivative | Gradient $\partial L/\partial(\cdot)$ |
|---|---|---|
| $\hat y$ | $\partial L/\partial \hat y = 2(\hat y - y)$ | $2(1.0242) = 2.0485$ |
| $w_2$ | $\partial \hat y/\partial w_2 = h$ | $2.0485 \times 0.4621 = 0.9466$ |
| $b_2$ | $\partial \hat y/\partial b_2 = 1$ | $2.0485$ |
| $h$ | $\partial \hat y/\partial h = w_2$ | $2.0485 \times 2 = 4.0969$ |
| $z$ | $\partial h/\partial z = 1 - h^2$ | $4.0969 \times (1 - 0.4621^2) = 3.2220$ |
| $w_1$ | $\partial z/\partial w_1 = x$ | $3.2220 \times 1 = 3.2220$ |
| $b_1$ | $\partial z/\partial b_1 = 1$ | $3.2220$ |

Notice what the backward pass needs: $h$ for $\partial L/\partial w_2$ and for $\tanh'$, $\hat y$ for the
first step, $x$ for the last. That is why the forward pass stores its intermediate values: memory is the
price of backpropagation.

In code, with a finite-difference check of one gradient:

```python
import numpy as np
x, y = 1.0, 0.0
w1, b1, w2, b2 = 0.5, 0.0, 2.0, 0.1

# forward pass: keep every intermediate value
z = w1 * x + b1
h = np.tanh(z)
y_hat = w2 * h + b2
L = (y_hat - y) ** 2

# backward pass: one local derivative per node, output first
dy_hat = 2 * (y_hat - y)
dw2 = dy_hat * h
db2 = dy_hat * 1
dh = dy_hat * w2
dz = dh * (1 - h ** 2)
dw1 = dz * x
db1 = dz * 1

def loss(w1, b1, w2, b2):
    return (w2 * np.tanh(w1 * x + b1) + b2 - y) ** 2
eps = 1e-6
print(f"dw1 = {dw1:.4f}, dw2 = {dw2:.4f}")
print(f"numeric dw1 = {(loss(w1 + eps, b1, w2, b2) - loss(w1 - eps, b1, w2, b2)) / (2 * eps):.4f}")

lr = 0.1
w1, b1, w2, b2 = w1 - lr * dw1, b1 - lr * db1, w2 - lr * dw2, b2 - lr * db2
print(f"loss before {L:.4f}, after one step {loss(w1, b1, w2, b2):.4f}")
```

```text title="Output"
dw1 = 3.2220, dw2 = 0.9466
numeric dw1 = 3.2220
loss before 1.0491, after one step 0.1430
```

A naming convention used from here on: `dw1` means $\partial L/\partial w_1$, always the derivative of
the *final loss*, never of some intermediate.

## Three patterns

Every graph, however large, is built from a few kinds of node. Knowing how gradient flows through them
makes backpropagation mechanical:

- **Add** ($u = a + b$): local derivatives are 1, so the gradient is **copied** unchanged to both inputs.
  That is why $\partial L/\partial b_2 = \partial L/\partial \hat y$.
- **Multiply** ($u = a \cdot b$): each input gets the gradient times the **other** input. So
  $\partial L/\partial w_2$ uses $h$ and $\partial L/\partial h$ uses $w_2$.
- **Branch** (a value used in several places): the gradients from all uses are **added**. This is the
  multivariable chain rule. In a layer, every input feeds every neuron, so its gradient is a sum over
  neurons.

## Vectorised: a layer at a time

Real networks work on matrices, but the same rules apply entry by entry. For a layer
$Z = AW + \mathbf{b}$ with $A$ $(n, d)$, $W$ $(d, m)$, $\mathbf{b}$ $(m,)$, suppose the layers above have
already given us $dZ = \partial L/\partial Z$, shape $(n, m)$. Then:

$$
dW = A^\top dZ \quad (d, m), \qquad
d\mathbf{b} = \textstyle\sum_{\text{rows}} dZ \quad (m,), \qquad
dA = dZ\,W^\top \quad (n, d)
$$

- $W_{jk}$ multiplies $A_{ij}$ in every example $i$ (multiply rule), and the examples' contributions add
  (branch rule): $dW_{jk} = \sum_i A_{ij}\,dZ_{ik}$, which is $A^\top dZ$.
- $\mathbf{b}$ is added to every row (add rule, then branch), so $d\mathbf{b}$ sums $dZ$ over the rows.
- $A_{ij}$ feeds every neuron $k$ through weight $W_{jk}$ (branch), so $dA_{ij} = \sum_k dZ_{ik}W_{jk}$,
  which is $dZ\,W^\top$.

For an element-wise activation $A = g(Z)$, the gradient is multiplied entry by entry by the slope:
$dZ = dA \odot g'(Z)$, written `dA * g_prime(Z)` in NumPy.

:::tip[Let the shapes tell you]
A gradient always has the same shape as the thing it is the gradient of. If you forget whether it is
$A^\top dZ$ or $dZ\,A^\top$ or $dZ^\top A$, write the shapes down: only $A^\top dZ$ turns $(d, n)$ and
$(n, m)$ into the $(d, m)$ that $dW$ must be.
:::

## A two-layer network, forward and backward

Here is the complete gradient of a classifier with one tanh hidden layer and softmax cross-entropy. The
first line of the backward pass is the $(P - Y)/n$ from [lesson 4](/foundations/f9/loss-functions/);
every line after it is one of the rules above.

```python
import numpy as np

def log_softmax(Z):
    m = Z.max(axis=1, keepdims=True)
    return Z - m - np.log(np.exp(Z - m).sum(axis=1, keepdims=True))

def loss_and_grads(p, X, y):
    n = len(y)
    # forward
    Z1 = X @ p["W1"] + p["b1"]           # (n, h)
    H = np.tanh(Z1)                      # (n, h)
    Z2 = H @ p["W2"] + p["b2"]           # (n, k)
    logp = log_softmax(Z2)
    loss = -logp[np.arange(n), y].mean()
    # backward
    dZ2 = np.exp(logp)                   # softmax probabilities ...
    dZ2[np.arange(n), y] -= 1            # ... minus one-hot labels
    dZ2 /= n                             # (n, k)
    g = {}
    g["W2"] = H.T @ dZ2                  # (h, n) @ (n, k) -> (h, k)
    g["b2"] = dZ2.sum(axis=0)            # (k,)
    dH = dZ2 @ p["W2"].T                 # (n, k) @ (k, h) -> (n, h)
    dZ1 = dH * (1 - H ** 2)              # tanh'(Z1) = 1 - tanh(Z1)^2
    g["W1"] = X.T @ dZ1                  # (d, n) @ (n, h) -> (d, h)
    g["b1"] = dZ1.sum(axis=0)            # (h,)
    return loss, g
```

We never need $dX$, since the inputs are not parameters, so the backward pass stops at the first layer.

### Check it

A gradient with a bug still produces numbers, and training may even seem to work a little. So compare
with central differences, using the relative error from
[F6](/foundations/f6/practical-optimisation/): nudge each parameter entry up and down by $\varepsilon$,
re-run the forward pass, and compare.

```python
rng = np.random.default_rng(0)
n, d, h, k = 6, 3, 5, 4
X = rng.normal(size=(n, d))
y = rng.integers(0, k, size=n)
p = {"W1": rng.normal(size=(d, h)), "b1": rng.normal(size=h),
     "W2": rng.normal(size=(h, k)), "b2": rng.normal(size=k)}

loss, g = loss_and_grads(p, X, y)

def numerical_grad(name, eps=1e-6):
    num = np.zeros_like(p[name])
    for idx in np.ndindex(p[name].shape):    # every index of the array, any shape
        old = p[name][idx]
        p[name][idx] = old + eps; up, _ = loss_and_grads(p, X, y)
        p[name][idx] = old - eps; down, _ = loss_and_grads(p, X, y)
        p[name][idx] = old
        num[idx] = (up - down) / (2 * eps)
    return num

for name in ["W1", "b1", "W2", "b2"]:
    num = numerical_grad(name)
    rel = np.linalg.norm(g[name] - num) / (np.linalg.norm(g[name]) + np.linalg.norm(num))
    print(f"{name}: shape {g[name].shape}, relative error {rel:.1e}")
```

```text title="Output"
W1: shape (3, 5), relative error 6.8e-10
b1: shape (5,), relative error 2.9e-10
W2: shape (5, 4), relative error 3.6e-10
b2: shape (4,), relative error 3.0e-10
```

Errors around $10^{-9}$ mean the gradient is right (the exact digits depend on your machine). A missing
`/ n`, or `(1 - H)` where `(1 - H ** 2)` belongs, would give errors near $10^{-1}$ or larger. Gradient checks are slow, so use a
tiny network and a few examples, and run them once whenever you change the backward pass.

:::caution[ReLU and gradient checks]
ReLU has a kink at 0. If a nudge of $\pm\varepsilon$ moves some $Z$ across 0, the finite difference is
wrong, not your gradient. With random inputs this is rare; if one entry disagrees and the rest match,
suspect a kink.
:::

## Summary

- Forward pass: compute and store every intermediate value. Backward pass: start from
  $\partial L/\partial L = 1$ and multiply by local derivatives node by node towards the parameters.
- Add copies gradient, multiply swaps in the other factor, branching sums gradients.
- Linear layer: $dW = A^\top dZ$, $d\mathbf{b}$ = column sums of $dZ$, $dA = dZ\,W^\top$; activation:
  $dZ = dA \odot g'(Z)$. Shapes always match the original arrays.
- Always check a new backward pass against finite differences; relative errors near $10^{-7}$ or below
  are good.
