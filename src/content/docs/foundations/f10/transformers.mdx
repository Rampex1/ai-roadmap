[Attention](/foundations/f10/attention/) lets tokens exchange information. A
<Term id="transformer" cap /> stacks that operation with the [MLP](/foundations/f9/forward-pass/) you built
in F9, adds two pieces of plumbing that make deep stacks trainable, and repeats the result many times.
This lesson assembles a GPT-style (decoder-only) transformer and then describes, at a high level, how
such models become chat assistants. Track B (B7, B8) derives and builds all of it in depth.

## The transformer block

The input to a block is a $(T, d)$ matrix: one $d$-dimensional vector per position, sometimes called the
**residual stream**. A GPT-style block does two things to it:

$$
\begin{aligned}
X &\leftarrow X + \operatorname{MultiHeadAttention}(\operatorname{LN}(X)) \\
X &\leftarrow X + \operatorname{MLP}(\operatorname{LN}(X))
\end{aligned}
$$

- **Causal multi-head self-attention** moves information *between* positions.
- The **MLP** (two linear layers with a non-linearity between, usually $d \to 4d \to d$) processes each
  position *separately*, with the same weights at every position. It is often described as where much
  of the model's stored knowledge lives.
- **LN** is <Term id="layer-normalisation" />, explained next.
- The `X +` is a <Term id="residual-connection" />.

The output has the same shape as the input, so blocks stack: GPT-2 small has 12, large models have many
dozens.

### Residual connections

Each sub-layer computes a *change* that is added to its input rather than replacing it. Two benefits:

- **Gradients flow.** The derivative of $X + f(X)$ with respect to $X$ is $1 + f'(X)$: there is always a
  direct path back to early layers, so gradients do not vanish through depth (the problem you met in
  [F9](/foundations/f9/training-an-mlp/)).
- **Easy to start.** A block that has learned nothing useful can output nearly zero and leave the stream
  unchanged.

### Layer normalisation

Layer normalisation rescales **each position's vector** to mean 0 and variance 1 across its $d$
features, then applies a learned scale $\boldsymbol\gamma$ and shift $\boldsymbol\beta$:

$$
\operatorname{LN}(\mathbf{x}) = \boldsymbol\gamma \odot \frac{\mathbf{x} - \mu}{\sqrt{\sigma^2 + \epsilon}} + \boldsymbol\beta
$$

where $\mu$ and $\sigma^2$ are the mean and variance of the entries of $\mathbf{x}$, $\epsilon$ is a tiny
constant that prevents division by zero, and $\odot$ is element-wise multiplication. It keeps the
numbers entering each sub-layer at a steady scale however the stream grows.

```python
import numpy as np
np.set_printoptions(precision=3, suppress=True)

def layer_norm(X, gamma, beta, eps=1e-5):
    mu = X.mean(axis=-1, keepdims=True)           # one mean per row (position)
    var = X.var(axis=-1, keepdims=True)
    return gamma * (X - mu) / np.sqrt(var + eps) + beta

x = np.array([[1.0, 2.0, 3.0, 6.0], [100.0, 102.0, 98.0, 100.0]])
y = layer_norm(x, np.ones(4), np.zeros(4))
print(y)
print(y.mean(axis=-1), y.std(axis=-1))
```

```text title="Output"
[[-1.069 -0.535  0.     1.604]
 [ 0.     1.414 -1.414  0.   ]]
[-0.  0.] [1. 1.]
```

The original 2017 transformer normalised *after* adding the residual; GPT-2 and most later models
normalise the sub-layer's input, as above ("pre-norm"), which trains more stably. Many recent models use
a simplified variant called RMSNorm.

## Where is the word order?

Attention compares every query with every key, and nothing in that computation knows *where* a token
sits. Without extra information, shuffling the input tokens just shuffles the outputs the same way:

```python
def softmax(Z):
    Z = Z - Z.max(axis=-1, keepdims=True)
    E = np.exp(Z)
    return E / E.sum(axis=-1, keepdims=True)

def attention(X, Wq, Wk, Wv):                     # no mask, to show the effect clearly
    Q, K, V = X @ Wq, X @ Wk, X @ Wv
    return softmax(Q @ K.T / np.sqrt(K.shape[1])) @ V

rng = np.random.default_rng(0)
X = rng.normal(size=(4, 8))
Wq, Wk, Wv = (rng.normal(size=(8, 8)) for _ in range(3))
perm = [3, 1, 0, 2]
print(np.allclose(attention(X[perm], Wq, Wk, Wv), attention(X, Wq, Wk, Wv)[perm]))
```

```text title="Output"
True
```

So "dog bites man" and "man bites dog" would look like the same bag of tokens. The fix is to add
<Term id="positional-encoding" text="positional information" /> to the input. GPT-2 learns a second
embedding table with one row per position and adds it to the token embedding:

$$
X = E_\text{token}[\text{ids}] + E_\text{pos}[0, 1, \dots, T-1]
$$

The original transformer added fixed sine and cosine patterns instead. Many recent open models instead
rotate the query and key vectors by a position-dependent angle (rotary embeddings, RoPE), which makes
attention scores depend on the *distance* between tokens.

## The whole model

A GPT-style language model is:

1. **Embed:** token embeddings plus position embeddings, giving $(T, d)$.
2. **Transform:** $N$ blocks, each attention then MLP, with residuals and layer norms.
3. **Unembed:** a final layer norm, then a linear layer from $d$ to $V$ giving logits for every position.
   It often reuses the token embedding matrix (**weight tying**).
4. **Softmax** each position's logits into a next-token distribution, exactly as in the
   [bigram lesson](/foundations/f10/language-models/).

### Counting parameters

Per block: attention has four $d \times d$ matrices ($W_Q$, $W_K$, $W_V$ for all heads together, and
$W_O$); the MLP has a $d \times 4d$ and a $4d \times d$ matrix. That is $12d^2$ weights, plus small bias
and layer norm vectors. For GPT-2 small ($V = 50{,}257$, context 1,024, $d = 768$, 12 blocks, tied
output layer):

```python
V, T, d, L = 50257, 1024, 768, 12
per_block = (4 * d * d + 4 * d) + (8 * d * d + 5 * d) + 4 * d   # attention, MLP, two layer norms
total = V * d + T * d + L * per_block + 2 * d                    # embeddings, blocks, final layer norm
print(per_block, total)
```

```text title="Output"
7087872 124439808
```

About 124 million parameters, almost a third of them in the token embedding table. GPT-3 (2020) used the
same design with 96 blocks and $d = 12{,}288$ for 175 billion.

## How GPT-style models are trained

### 1. Pretraining

The model reads an enormous amount of text (web pages, books, code) and learns by
[next-token prediction](/foundations/f10/language-models/): cross-entropy loss at every position, with the
causal mask letting all positions of a sequence train in parallel. This is <Term id="pretraining" />.
GPT-3 saw about 300 billion tokens; Meta reported pretraining Llama 3 (2024) on over 15 trillion. Nobody
labels anything: the next token is the label.

Predicting text well forces the model to absorb grammar, facts, styles of reasoning and code. The result
is a **base model**: an excellent document continuer, but not an assistant. Asked "What is the capital of
France?", a base model may continue with more quiz questions instead of answering.

### 2. Instruction tuning

Next, <Term id="instruction-tuning" /> (supervised fine-tuning) continues training on curated examples of
prompts paired with good responses, written or checked by people, often formatted as conversations. The
loss is still next-token cross-entropy, usually counted only on the response tokens. The model learns the
*format* of being helpful: answer the question, follow the instruction, stop.

### 3. Preference tuning

Finally, the model is tuned towards responses people prefer. In <Term id="rlhf" text="RLHF" />
(reinforcement learning from human feedback), people compare pairs of responses, a **reward model** is
trained to predict their preferences, and the language model is optimised to earn high reward while a
penalty (a KL divergence, a measure of how far one distribution is from another; see
[F5](/foundations/f5/information-theory/)) keeps it close to the instruction-tuned model. Simpler methods such as
DPO learn from the preference pairs directly. As of late 2026, models are also trained with
reinforcement learning on tasks whose answers can be checked automatically, such as maths and code,
which produces the "reasoning" models that write long chains of intermediate steps before answering.

Pretraining takes almost all of the compute; post-training is comparatively cheap but shapes most of the
behaviour you see in a chat assistant. C10 implements the DPO loss and B8 covers the data side (shifted targets, loss masks, preference
evaluation); reward-model RLHF is beyond this course.

### Context windows

A model is trained on sequences up to some maximum length, its <Term id="context-window" />: everything
it can see at once, prompt and answer together. GPT-2's was 1,024 tokens. As of late 2026, widely used
models advertise windows from about 128,000 to over a million tokens. Anything outside the window does not
exist for the model, and, because attention cost grows with the square of the length, long contexts are
slower and dearer.

### Scaling

Studies around 2020 found that a language model's loss falls smoothly and predictably, roughly as a
power law, as you increase parameters $N$, training tokens $D$ and compute. Two rules of thumb:

- Training compute is about $6ND$ floating-point operations (FLOPs).
- The 2022 "Chinchilla" study found that, for a fixed compute budget, about 20 training tokens per
  parameter gave the lowest loss. Many current models train on far more tokens per parameter than that,
  because a smaller model is cheaper to run once deployed.

For a 124-million-parameter model at 20 tokens per parameter:

```python
N = 124e6
D = 20 * N
print(f"{D:.3g} tokens, {6 * N * D:.3g} FLOPs")
```

```text title="Output"
2.48e+09 tokens, 1.85e+18 FLOPs
```

A single data-centre GPU sustains very roughly $10^{14}$ to $10^{15}$ FLOPs per second in practice (as
of late 2026, depending on its generation and number format), so that is somewhere between about half an
hour and 5 hours. Frontier models use many orders of magnitude more, on thousands of GPUs
for months. Scale explains much of the progress since 2018, but not all of it: data quality and
post-training matter enormously.

## Summary

- A transformer block is $X \leftarrow X + \operatorname{Attn}(\operatorname{LN}(X))$ then
  $X \leftarrow X + \operatorname{MLP}(\operatorname{LN}(X))$: attention mixes positions, the MLP processes
  each position; blocks keep the $(T, d)$ shape and stack.
- Residual connections give gradients a direct path; layer normalisation keeps each position's vector at
  mean 0 and variance 1 before the learned scale and shift.
- Attention ignores order, so position embeddings (learned, sinusoidal or rotary) are added.
- A GPT model is embed, $N$ blocks, final norm, a linear layer to $V$ logits and a softmax; each block has
  about $12d^2$ parameters.
- Chat models are pretrained on next-token prediction over trillions of tokens, then instruction-tuned,
  then preference-tuned (RLHF or similar).
- Training compute is about $6ND$; loss improves predictably with scale.
