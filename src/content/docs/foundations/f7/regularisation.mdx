Lesson 3 offered two ways to stop a model overfitting: give it less freedom (a lower degree) or give it
more data. <Term id="regularisation" cap /> is a third: keep the flexible model, but charge it for using its
flexibility. The charge is a **penalty** on the size of the weights, added to the loss.

## Overfit models have huge weights

Refit lesson 3's degree-15 polynomial, this time with standardised features (more on why below), and
look at its weights:

```python
import numpy as np
from sklearn.model_selection import train_test_split
from sklearn.pipeline import make_pipeline
from sklearn.preprocessing import PolynomialFeatures, StandardScaler
from sklearn.linear_model import LinearRegression, Ridge
from sklearn.metrics import mean_squared_error

rng = np.random.default_rng(0)
x = rng.uniform(-1, 1, 60)
y = np.sin(3 * x) + rng.normal(0, 0.3, 60)
X = x.reshape(-1, 1)
X_tr, X_rest, y_tr, y_rest = train_test_split(X, y, test_size=0.4, random_state=0)
X_val, X_te, y_val, y_te = train_test_split(X_rest, y_rest, test_size=0.5, random_state=0)

plain = make_pipeline(PolynomialFeatures(15, include_bias=False), StandardScaler(), LinearRegression()).fit(X_tr, y_tr)
print(f"no penalty:  largest |weight| {np.abs(plain[-1].coef_).max():.3g}  validation MSE {mean_squared_error(y_val, plain.predict(X_val)):.3f}")
for alpha in [0.001, 0.1, 10]:
    model = make_pipeline(PolynomialFeatures(15, include_bias=False), StandardScaler(),
                          Ridge(alpha=alpha)).fit(X_tr, y_tr)
    val = mean_squared_error(y_val, model.predict(X_val))
    print(f"alpha {alpha:<6}  largest |weight| {np.abs(model[-1].coef_).max():7.3f}  validation MSE {val:.3f}")
```

```text title="Output"
no penalty:  largest |weight| 5.55e+03  validation MSE 23.622
alpha 0.001   largest |weight|   4.376  validation MSE 0.398
alpha 0.1     largest |weight|   1.433  validation MSE 0.289
alpha 10      largest |weight|   0.500  validation MSE 0.422
```

(`model[-1]` is the last step of the pipeline, the fitted regressor.) Unpenalised, the fit uses
weights in the thousands that almost cancel each other out, and that is what makes it swing between
the data points. A tiny penalty shrinks them by a factor of a thousand and cuts the validation error
from 23.6 to 0.4. Too strong a penalty ($\alpha = 10$) flattens the curve and the error rises again: the
penalty strength is itself a bias–variance dial.

## Ridge: an L2 penalty

<Term id="ridge-regression" text="Ridge regression" /> adds the squared length of the weight vector to
the squared error. scikit-learn's `Ridge` minimises

$$
\lVert \mathbf{y} - X\mathbf{w} - b \rVert^2 + \alpha \lVert \mathbf{w} \rVert^2
= \sum_{i=1}^{n} (y_i - \mathbf{w}\cdot\mathbf{x}_i - b)^2 + \alpha \sum_{j=1}^{d} w_j^2
$$

where $\alpha \ge 0$ is the penalty strength, a hyperparameter. Two things to notice:

- The intercept $b$ is **not** penalised. Shrinking it would just shift every prediction towards zero,
  which has nothing to do with complexity.
- $\alpha = 0$ is ordinary least squares, and $\alpha \to \infty$ forces every weight to 0, leaving
  only the intercept: the mean baseline.

Ridge keeps a closed form. If you centre the data first (subtract each column's mean from $X$ and the
mean from $\mathbf{y}$), the intercept drops out and setting the gradient to zero gives

$$
(X_c^\top X_c + \alpha I)\,\mathbf{w} = X_c^\top \mathbf{y}_c, \qquad b = \bar{y} - \bar{\mathbf{x}}\cdot\mathbf{w}
$$

Compared with the normal equations, the only change is $+\alpha I$, which also makes the matrix
invertible even when features are collinear, a numerical bonus.

```python
rng = np.random.default_rng(0)
X = rng.normal(size=(50, 3)); y = X @ np.array([1.0, 2.0, -1.0]) + 5 + rng.normal(0, 0.5, 50)
alpha = 10.0
x_mean, y_mean = X.mean(axis=0), y.mean()
Xc, yc = X - x_mean, y - y_mean            # centre, so the intercept is not penalised
w = np.linalg.solve(Xc.T @ Xc + alpha * np.eye(3), Xc.T @ yc)
b = y_mean - x_mean @ w
sk = Ridge(alpha=alpha).fit(X, y)
print(w.round(4), round(b, 4))
print(sk.coef_.round(4), round(sk.intercept_, 4))
```

```text title="Output"
[ 0.9302  1.5196 -0.7497] 4.8906
[ 0.9302  1.5196 -0.7497] 4.8906
```

The true weights are $(1, 2, -1)$; ridge has pulled all three towards zero. On this clean dataset the
shrinkage only costs accuracy. Its value shows when there are many features and little data.

:::note[Same idea, other names]
For a model trained by gradient descent, the penalty $\alpha\lVert\mathbf{w}\rVert^2$ adds $2\alpha\mathbf{w}$ to the
gradient, so every step also shrinks each weight a little towards zero. Neural network libraries call
this **weight decay** (F9). Statisticians also call ridge *Tikhonov regularisation*.
:::

## Lasso: an L1 penalty

<Term id="lasso" text="Lasso" /> penalises the sum of absolute values instead. scikit-learn's `Lasso`
minimises

$$
\frac{1}{2n}\lVert \mathbf{y} - X\mathbf{w} - b \rVert^2 + \alpha \lVert \mathbf{w} \rVert_1,
\qquad \lVert \mathbf{w} \rVert_1 = \sum_{j} |w_j|
$$

(The $\frac{1}{2n}$ scaling differs from `Ridge`, so the same `alpha` means different strengths in the
two classes.) The difference in behaviour is striking. Eight features, of which only the first three
matter:

```python
from sklearn.linear_model import Lasso

rng = np.random.default_rng(0)
n, d = 100, 8
X = rng.normal(size=(n, d))
true_w = np.array([4.0, -3.0, 2.0, 0, 0, 0, 0, 0])   # only 3 features matter
y = X @ true_w + rng.normal(0, 1.0, n)

for alpha in [0.1, 0.5, 1.0]:
    print(f"lasso alpha={alpha}:", Lasso(alpha=alpha).fit(X, y).coef_.round(2) + 0.0)
print("ridge alpha=50: ", Ridge(alpha=50).fit(X, y).coef_.round(2) + 0.0)
```

```text title="Output"
lasso alpha=0.1: [ 3.75 -2.82  1.85 -0.05  0.    0.05  0.    0.  ]
lasso alpha=0.5: [ 3.24 -2.37  1.35  0.    0.    0.    0.    0.  ]
lasso alpha=1.0: [ 2.6  -1.79  0.72  0.    0.    0.    0.    0.  ]
ridge alpha=50:  [ 2.34 -1.81  1.14 -0.21  0.08  0.21  0.    0.29]
```

(The `+ 0.0` only turns NumPy's printed `-0.` into `0.`.) Lasso sets the useless weights to **exactly
zero**: it selects features. Ridge shrinks everything but leaves small non-zero weights on the noise
features.

Why the difference? Look at the penalty's slope. The ridge penalty $w^2$ has derivative $2w$, which
vanishes as $w$ approaches 0: the push towards zero gets weaker and weaker, so a weight never quite gets
there. The lasso penalty $|w|$ has slope $\pm 1$ all the way down: a constant push. If a feature's
benefit to the fit is smaller than that push, the best value for its weight is exactly 0. (Because
$|w|$ has a kink at 0, lasso has no closed form; scikit-learn fits it by coordinate descent.)

| | Ridge (L2) | Lasso (L1) |
|---|---|---|
| Penalty | $\alpha\sum_j w_j^2$ | $\alpha\sum_j \lvert w_j \rvert$ |
| Effect on weights | shrinks all, none to exactly 0 | shrinks, many exactly to 0 |
| Closed form | yes | no |
| Use when | many small effects, correlated features | you expect few features to matter, or want a simpler model |

`ElasticNet` mixes the two penalties, for when you want sparsity but have groups of correlated
features.

## Scale first

The penalty treats every weight the same, but a weight's size depends on its feature's units. Measure
a distance in metres instead of kilometres and its weight must become 1,000 times smaller for the same
prediction, so the penalty barely touches it. Same data, same model, different answer:

```python
rng = np.random.default_rng(0)
X = rng.normal(size=(100, 2)); y = X @ np.array([3.0, 3.0]) + rng.normal(0, 1, 100)
print(Ridge(alpha=20).fit(X, y).coef_.round(2))
X_m = X.copy(); X_m[:, 1] = X[:, 1] * 1000     # feature 2 in metres instead of km
print(Ridge(alpha=20).fit(X_m, y).coef_.round(5) * [1, 1000])   # back to per-km units
```

```text title="Output"
[2.44 2.65]
[2.37647 3.25   ]
```

After converting the second weight back to per-kilometre units it is $3.25$ instead of $2.65$: it has
escaped the penalty. The fix is to standardise every feature
([F6's feature scaling](/foundations/f6/practical-optimisation/)) before a penalised model, which is
why the first example put a `StandardScaler` in the pipeline.

## Choosing alpha

$\alpha$ is a hyperparameter, so choose it like the polynomial degree: try a range on a log scale (0.001,
0.01, ..., 1000), fit on the training set, and keep the value with the lowest validation error. Lesson 7
makes this more reliable with cross-validation; scikit-learn's `RidgeCV` and `LassoCV` do it in one call.

## Summary

- Regularisation adds a penalty on weight size to the loss, trading a little bias for less variance.
- Ridge (L2): $\lVert\mathbf{y} - X\mathbf{w} - b\rVert^2 + \alpha\lVert\mathbf{w}\rVert^2$, closed form
  $(X_c^\top X_c + \alpha I)^{-1}X_c^\top\mathbf{y}_c$; shrinks all weights.
- Lasso (L1): sets weights exactly to zero, so it selects features; no closed form.
- The intercept is not penalised. Standardise features first, because the penalty depends on units.
- Pick $\alpha$ on validation data, searching on a log scale.
