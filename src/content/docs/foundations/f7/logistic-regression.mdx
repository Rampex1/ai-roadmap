Now the label is a category: pass or fail, spam or not, malignant or benign. We code the two classes as
0 and 1. <Term id="logistic-regression" text="Logistic regression" /> is the standard first model for
this, and despite its name it is a classifier. It is also, almost exactly, a neural network with no
hidden layer, so everything here carries over to F9.

## Why not just use linear regression?

Twelve students, the hours they studied, and whether they passed:

```python
import numpy as np
from sklearn.linear_model import LinearRegression, LogisticRegression

hours = np.array([0.5, 1, 1.5, 2, 2.5, 3, 3.5, 4, 4.5, 5, 5.5, 6]).reshape(-1, 1)
passed = np.array([0, 0, 0, 0, 1, 0, 1, 0, 1, 1, 1, 1])

lin = LinearRegression().fit(hours, passed)
print("linear regression at 0 and 10 hours:", lin.predict([[0], [10]]).round(2))

clf = LogisticRegression().fit(hours, passed)
print("w =", clf.coef_.round(3), " b =", clf.intercept_.round(3))
print("P(pass) at 1, 3, 5, 10 hours:", clf.predict_proba([[1], [3], [5], [10]])[:, 1].round(3))
print("predicted class:", clf.predict([[1], [3], [5], [10]]))
```

```text title="Output"
linear regression at 0 and 10 hours: [-0.18  1.92]
w = [[1.008]]  b = [-3.276]
P(pass) at 1, 3, 5, 10 hours: [0.094 0.437 0.854 0.999]
predicted class: [0 0 1 1]
```

A straight line predicts a "probability" of $-0.18$ at 0 hours and $1.92$ at 10, which is meaningless.
Worse, a few students far out on the x-axis would tilt the whole line. Logistic regression keeps the
linear score but squashes it into $(0, 1)$.

## The model

Compute a linear score, then pass it through the <Term id="sigmoid" />
$\sigma(z) = \frac{1}{1 + e^{-z}}$:

$$
z = \mathbf{w}\cdot\mathbf{x} + b, \qquad p = P(y = 1 \mid \mathbf{x}) = \sigma(z)
$$

$\sigma$ maps $0$ to $0.5$, large positive $z$ towards 1 and large negative $z$ towards 0. For the
student data, $z = 1.008 \times \text{hours} - 3.276$, so 5 hours gives $z = 1.76$ and
$p = \sigma(1.76) = 0.854$.

**Reading the weights.** Solving $p = \sigma(z)$ for $z$ gives

$$
z = \ln\frac{p}{1 - p}
$$

the **log-odds**. So the model says the log-odds are linear in the features: each extra hour of study
adds $1.008$ to the log-odds of passing, which multiplies the odds by $e^{1.008} \approx 2.7$. This is
how statisticians and doctors read logistic regression coefficients.

## The loss: log loss is cross-entropy

To fit $\mathbf{w}$ and $b$ we need a loss. In [F5](/foundations/f5/maximum-likelihood/) you derived it:
if the model gives each example probability $p_i$ of being class 1, the average negative log-likelihood
of the observed labels is

$$
L(\mathbf{w}, b) = -\frac{1}{n}\sum_{i=1}^{n} \Big[y_i \ln p_i + (1 - y_i)\ln(1 - p_i)\Big]
$$

This is the binary <Term id="cross-entropy" /> from F5's
[information theory lesson](/foundations/f5/information-theory/), and scikit-learn calls it **log loss**
(`sklearn.metrics.log_loss`). When the true label is 1 the loss is $-\ln p_i$: tiny when $p_i$ is near 1,
huge when the model was confident and wrong.

Why not the mean squared error between $p_i$ and $y_i$? Combined with the sigmoid, MSE gives a non-convex
loss whose gradient almost vanishes when the model is confidently wrong, so learning stalls exactly when
it should be fastest. Log loss is **convex** in $\mathbf{w}$ and $b$: one valley, no bad local minima
([F6](/foundations/f6/what-is-optimisation/)).

## The gradient

By the chain rule ([F4](/foundations/f4/chain-rule/)), for one example with $p = \sigma(z)$:

$$
\frac{\partial L_i}{\partial p} = -\frac{y}{p} + \frac{1 - y}{1 - p}, \qquad
\frac{\partial p}{\partial z} = p(1 - p)
$$

Multiply and simplify, and almost everything cancels:

$$
\frac{\partial L_i}{\partial z} = -y(1 - p) + (1 - y)p = p - y
$$

The error signal is just *prediction minus label*. Since $z = \mathbf{w}\cdot\mathbf{x} + b$, averaging
over the examples gives

$$
\nabla_{\mathbf{w}} L = \frac{1}{n} X^\top(\mathbf{p} - \mathbf{y}), \qquad
\frac{\partial L}{\partial b} = \frac{1}{n}\sum_{i}(p_i - y_i)
$$

That is the same shape as linear regression's gradient, $\frac{2}{n}X^\top(\hat{\mathbf{y}} - \mathbf{y})$,
with probabilities in place of predictions. Setting it to zero has no closed-form solution (the $p_i$
are non-linear in $\mathbf{w}$), so we use F6's loop:

```python
from sklearn.metrics import log_loss

rng = np.random.default_rng(0)
n = 200
X = rng.normal(size=(n, 2))
y = (X @ np.array([2.0, -1.0]) + 0.5 + rng.normal(0, 1.0, n) > 0).astype(int)

def sigmoid(z):
    return 1 / (1 + np.exp(-z))

w, b, lr = np.zeros(2), 0.0, 0.5
for step in range(2001):
    p = sigmoid(X @ w + b)
    if step % 500 == 0:
        loss = -np.mean(y * np.log(p) + (1 - y) * np.log(1 - p))
        print(f"step {step:4d}  log loss {loss:.4f}")
    w -= lr * X.T @ (p - y) / n          # gradient of the mean log loss
    b -= lr * np.mean(p - y)

sk = LogisticRegression(C=1e6).fit(X, y)   # huge C: almost no penalty
print("GD:     ", w.round(3), round(b, 3))
print("sklearn:", sk.coef_[0].round(3), sk.intercept_.round(3)[0])
print("sklearn log_loss:", round(log_loss(y, sk.predict_proba(X)[:, 1]), 4))
```

```text title="Output"
step    0  log loss 0.6931
step  500  log loss 0.2711
step 1000  log loss 0.2711
step 1500  log loss 0.2711
step 2000  log loss 0.2711
GD:      [ 3.852 -1.872] 0.805
sklearn: [ 3.852 -1.873] 0.804
sklearn log_loss: 0.2711
```

The starting loss $0.6931 = \ln 2$ is what you get by predicting $p = 0.5$ for everyone. Our 20-line
loop and scikit-learn's optimiser (L-BFGS, a cleverer relative of gradient descent) land on the same
weights. The weights point in the direction of the true $(2, -1)$; their size depends on how noisy the
labels are, since less noise means the model can afford to be more confident.

## The decision boundary

To turn a probability into a class, compare it with a **threshold**, by default 0.5. Since
$\sigma(z) \ge 0.5$ exactly when $z \ge 0$, the model predicts class 1 when

$$
\mathbf{w}\cdot\mathbf{x} + b \ge 0
$$

The set where $\mathbf{w}\cdot\mathbf{x} + b = 0$ is the <Term id="decision-boundary" />. For the students
it is a single point: $1.008\,h - 3.276 = 0$ gives $h \approx 3.25$ hours. With two features it is the
straight line $w_1 x_1 + w_2 x_2 + b = 0$, and with $d$ features a flat hyperplane, perpendicular to
$\mathbf{w}$ ([F3](/foundations/f3/dot-product/)). Logistic regression is a **linear classifier**: it can
only separate classes with a straight cut. For curved boundaries, add polynomial features (lesson 2) or
use a different model (lesson 9).

The threshold does not have to be 0.5. Lesson 6 shows when to move it.

## LogisticRegression in practice

- `predict_proba(X)` returns an `(n, 2)` array: column 0 is $P(y = 0)$, column 1 is $P(y = 1)$. Take
  `[:, 1]` for the positive class. `predict(X)` applies the 0.5 threshold.
- **It is regularised by default.** scikit-learn adds an L2 penalty (lesson 4) controlled by `C`, the
  *inverse* of the strength: small `C` means a strong penalty. The default is `C=1.0`. That is why the
  student example used the default but the comparison with our loop used `C=1e6`.

```python
for C in [100, 1, 0.01]:
    m = LogisticRegression(C=C).fit(X, y)
    print(f"C={C:<5} coef {m.coef_[0].round(3)}  accuracy {m.score(X, y):.3f}")
```

```text title="Output"
C=100   coef [ 3.838 -1.866]  accuracy 0.865
C=1     coef [ 3.006 -1.433]  accuracy 0.865
C=0.01  coef [ 0.454 -0.199]  accuracy 0.850
```

A strong penalty shrinks the weights, so the probabilities move towards 0.5, but the boundary's
direction barely changes. As with ridge, **scale the features** first, and choose `C` by validation.
If you see a `ConvergenceWarning`, the optimiser ran out of iterations: scale the features or raise
`max_iter`.

- **More than two classes** work too. scikit-learn gives each class its own weight vector and turns the
  scores into probabilities with the <Term id="softmax" />, the multi-class sigmoid (F9 builds it from
  scratch):

```python
from sklearn.datasets import load_iris

X, y = load_iris(return_X_y=True)
clf = LogisticRegression(max_iter=1000).fit(X, y)
print(clf.coef_.shape)
print(clf.predict_proba(X[[0, 75, 149]]).round(3))
```

```text title="Output"
(3, 4)
[[0.982 0.018 0.   ]
 [0.005 0.92  0.075]
 [0.    0.235 0.764]]
```

Three classes, four features: a $3 \times 4$ weight matrix, and each row of probabilities sums to 1.

:::note[Probabilities you can trust?]
A logistic regression's probabilities are often reasonably *calibrated*: of the cases given 0.8, about
80% are positive. Strong regularisation or class re-weighting can break that.
[F11's calibration lesson](/foundations/f11/calibration-and-trade-offs/) shows how to check, and why it
matters when the same score is used for different groups of people.
:::

## Summary

- Logistic regression: $p = \sigma(\mathbf{w}\cdot\mathbf{x} + b)$, a probability for class 1; $z$ is the log-odds.
- The loss is log loss, the binary cross-entropy from F5's maximum likelihood; it is convex.
- Gradient: $\frac{1}{n}X^\top(\mathbf{p} - \mathbf{y})$, prediction minus label. No closed form, so it is
  trained iteratively.
- The decision boundary $\mathbf{w}\cdot\mathbf{x} + b = 0$ is a line or hyperplane: a linear classifier.
- `LogisticRegression` is L2-penalised by default with `C = 1/strength`; scale features, use
  `predict_proba(X)[:, 1]` for probabilities.
