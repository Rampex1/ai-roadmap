A <Term id="dataset-manifest" /> lets you reconstruct which rows and transformations were used. Record raw object digests, schema version, feature code version and split identities. A path such as current/train can be overwritten while keeping its name. Store immutable references and verify hashes whenever the same content is required.

A manifest hash identifies the exact serialized description. Canonicalize object-key order and separators before hashing. Some list order can be meaningful, as with a declared column order or sequence of shards, so preserve it unless the manifest contract explicitly defines a set. Keep sensitive row content out of the manifest.

The example serializes a restricted JSON manifest using sorted keys and compact separators, then hashes UTF-8 bytes. It assumes finite values and string keys. This provides deterministic identity for the given serialization rules. It cannot verify content unless the referenced objects are hashed and checked too.

## Worked example

A change in object key insertion order leaves the canonical bytes unchanged.

```python
def manifest_digest(manifest):
    import hashlib
    import json
    encoded = json.dumps(manifest, sort_keys=True, separators=(",", ":"), ensure_ascii=False, allow_nan=False)
    return hashlib.sha256(encoded.encode("utf-8")).hexdigest()

print(manifest_digest({"split":"train","schema":1}) == manifest_digest({"schema":1,"split":"train"}))
```

```text title="Output"
True
```

Pair a versioned manifest with checksums for the actual data objects and code references.
